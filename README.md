# Dominion 棋譜ビューアー

Dominion Onlineの対戦ログ・取り込みJSONを読み込み、対局を最初から再生したり、任意の場面へ進んだり戻ったりできる非公式の振り返り用ツールです。

現在の配布版は **6.9.1**。WindowsのGoogle Chromeを優先して開発しています。

[ビューアーを開く](./index.html)

## 使い方

1. 上のリンクを開く。ダウンロードした `index.html` をChromeで開く方法でも使えます。
2. 「JSON・ログを読み込む」から、対戦ログまたは取り込みJSONを貼り付ける。ファイルからの読み込みもできます。
3. 片側視点だけなら入力欄を1つ使い、両側の記録がある場合はそれぞれ別の欄へ貼ります。両視点をまとめたJSONは、1つの欄だけへ貼ってください。
4. 再生・進む・戻る・ターン選択・タイムライン・ログ行のクリックで場面を移動します。
5. 「表示設定」でアニメーション、表示言語、対局者名、振り返り用の山札内容などを調整できます。

カードをクリックすると拡大画像・効果を表示します。サプライを右クリックすると山の内訳を確認できます。廃棄場、捨て札、マット、場に残るカードなども開けます。詳細画面は枠外のクリックまたはEscで閉じられます。

片側視点では判明していない相手のカードを隠して表示します。両視点を照合すると、記録から補完できる非公開情報を表示できます。両視点があっても、記録にない山札順などがすべて分かるわけではありません。

## 入力形式

| 形式 | 内容 |
| --- | --- |
| テキストログ | 日本語・英語の対戦ログ |
| `dominion-replay-record/v1` | 1視点の構造化された取り込み記録 |
| `dominion-replay-pair/v1` | 両視点の取り込み記録 |
| `dominion-replay-logs` | `log1`・`log2`を持つ保存済みテキストログ |

`dominion-import-check/v1` は取得機能の確認用であり、棋譜本体としては読み込めません。ゲーム番号だけから対戦を取得する機能はありません。JSONの取得には別途取り込みツールが必要です。

## JSONの取得：Chrome用の取り込み拡張

[取り込み拡張をダウンロード（ZIP）](./dominion-import-extension.zip)

これは別途Chromeに読み込む拡張機能です。ビューアーを開くだけではインストールされません。終了済み対局のコピー／保存用で、対戦操作の自動化は行いません。現在の版は **0.2.3** です。

### 最初の1回：拡張を入れる

1. 上のZIPをダウンロードし、Windowsで右クリック→「すべて展開」を選ぶ。
2. Chromeのアドレス欄に `chrome://extensions` を入力して開く。
3. 右上の「デベロッパー モード」をオンにする。
4. 「パッケージ化されていない拡張機能を読み込む」を押す。
5. 展開した中の `dominion-import-probe` フォルダを選ぶ。`manifest.json` が入っているフォルダを選ぶこと。
6. バージョン0.2.3を確認し、Dominion Onlineのタブを再読み込みする。

以前の同じ拡張や「棋譜取り込み確認」を入れている場合は、古い方をオフにしてから新しいものを読み込んでください。

### 1視点の棋譜をコピーする

1. Dominion Onlineで、自分がホストの通常の卓の「過去ゲームを読み込む」を開く。
2. ゲーム番号を入力し、公式の「終局から読み込む」を押す。
3. 取得する席を確認する。席を変える場合は、読み込み後、準備完了を押す前に参加者一覧の上下の矢印で変更する。
4. 準備完了を押して終局を表示し、終了通知を閉じて「卓の編集」へ戻る。
5. **この後はページを再読み込みせず**、「過去ゲームを読み込む」を再び開く。番号が空なら同じ番号を入力する。
6. 拡張の「棋譜をコピー」を左クリックする。
7. ビューアーの「JSON・ログを読み込む」を開き、入力欄1つへCtrl+Vで貼り付けて読み込む。

「棋譜をコピー」の右クリック、またはShiftを押しながら左クリックするとJSONファイルへ保存します。保存したファイルはビューアーから読み込めます。Chromeがコピーを許可しない場合もファイル保存へ切り替わります。ボタンが無効な場合は、マウスを乗せて理由を確認してください。

### 両視点をまとめる

1. 最初の席で、上の手順に沿って「棋譜をコピー」を押す。記録がそのタブ内に一時保持される。
2. **同じタブを再読み込みせず**、同じゲーム番号・読み込み位置を、反対側の席で読み込み直す。
3. 再び準備完了→終了通知を閉じる→卓の編集→過去ゲームの読み込み欄へ戻る。
4. もう一度「棋譜をコピー」を押す。両視点が照合できれば、まとめたJSONがコピーされる。
5. そのJSONはビューアーの欄1つに貼り、もう一方の欄は空にする。

タブを閉じたり再読み込みしたりすると、拡張の一時保持は消えます。別々に保存済みの2つのJSONを、ビューアーの2つの欄へそれぞれ読み込む方法でも利用できます。

この版では、読み込み・準備完了・終了は各視点で手動操作が必要です。公式の終局読み込みはコピー対局を再開するため、Bot等が元の対局より先まで操作する場合があります。ビューアーでは両視点の共通する処理と、片側だけの末尾を区別します。取得したコピー対局の番号を、元のゲーム番号として断定しません。

拡張のボタンは非対戦状態の過去ゲーム読み込み欄で使います。対戦中・開始中・大会卓・順位戦卓などでは有効にせず、クリップボードは読みません。大会等の利用ルールは主催者の指定に従ってください。

## 配布構成

- `index.html`：プログラム、カード画像、データをまとめた単一HTML。サーバー側の処理やnpmのインストールは不要です。
- `README.md`：この説明。
- `dominion-import-extension.zip`：JSONを取得するChrome拡張。展開してChromeへ読み込む。

棋譜の解析はブラウザ内で行います。初期画面は空で、既定の棋譜・王国サプライは埋め込みません。カードの詳細ルールへのリンクは外部の[ドミニオンWiki](https://wikiwiki.jp/dominiondeck/)を開きます。

## 開発・修正を担当する人／LLMへ

### 最初に確認すること

このリポジトリが `index.html` だけを置いている場合、そのファイルはビルド済みの配布物です。可能なら管理者から編集用ソース一式を入手してください。以下の `work/` 内のファイルは、編集用ソース一式に含まれるもので、配布リポジトリに必ず存在するとは限りません。

ソースがある場合は生成済みHTMLの巨大なデータ部分を直接編集せず、対応するJavaScript・CSS・テンプレートを修正して再ビルドしてください。ファイル名末尾の `v4`・`v68` などはモジュールの世代であり、アプリ全体の現在のバージョンではありません。

取り込み拡張のソースは配布ZIP内の `dominion-import-probe/` にあります。`manifest.json` の順に `record.js`・`pair.js`・`probe.js` を読み込みます。取得ボタンの表示条件を緩めたり、ゲーム操作や自動読み込みを追加したりしないでください。確認用JSONと棋譜本体を区別し、出所・元の設定・コピー対局の結果を別々に保持してください。

### 維持する仕様

- このツールは記録に沿って状態を復元するビューアーです。プレイヤーの選択や未記録の効果を勝手に実行する対戦エンジンへ変えないでください。
- 判明した情報と推定・不明な情報を区別してください。単視点の非公開情報を生成しないでください。完成時の残数や手札を、途中の状態へそのまま流用しないでください。
- 両視点の対応は席と処理の照合を使います。表示名だけで同一プレイヤーを決めないでください。投了後やBotによる片側だけの継続は、共通する範囲と区別してください。
- 先手・後手の上下位置は固定し、視点反転を可能にしてください。手番ごとに両者の手札位置を入れ替えないでください。サプライは手番と反対側へ動かし、出札のスペースを確保してください。
- 基本カードは左の縦2列、王国カードは上下2段、景観は右に配置してください。10山固定にせず、廃墟・分割山・サプライ外の山などを扱ってください。
- カード画像、種類の色、縦長の比率を維持してください。枚数は左上、カードの絵を隠さない大きさにしてください。場は使用順で並べ、AABAはA×2・B・Aと表示してください。再使用で物理カード枚数を増やさないでください。
- 画面全体の縦スクロールを抑えてください。出札が多い場合は縮小・折り返しを使い、右端を切らないでください。操作は右側のログ下を基本にしてください。
- 使用→効果→ドローを順に見せ、手札の詰め直し、サプライ移動、シャッフルにも動きを付けてください。動きを無効にする設定と速度変更を維持してください。
- 山札枚数を常時表示し、判明した捨て札トップは両者に表示してください。資源・トークン・持続カード・追放等のマットも確認できるようにしてください。
- 公開・確認の入れ子に対応してください。処理中に別の確認が始まる場合は複数の窓を扱い、完了した窓は閉じてください。窓は画面外へ切らず、移動・サイズ変更を可能にしてください。
- 残り山札の内容など振り返り用の非公開情報は、表示設定で切り替えられるようにしてください。実戦中の支援機能や対戦操作の自動化を追加しないでください。

### 間違えやすいルールと修正済みの例

- **獲得元と獲得先は別々に判定する。** 彫刻家・鷹匠・カブラー等の手札獲得、武器庫・工匠等の山札獲得、廃棄場やサプライ外からの獲得を通常の捨て札獲得と混同しない。
- **交換は獲得ではない。** 交換で受け取るカードは通常捨て札へ入る。元の獲得先を引き継いだり、獲得時効果を再発生させたりしない。
- **移動阻止は元の場所とカードを参照する。** 望楼で移したセイレーンを後の自己廃棄が追いかけたり、同名の別カードを動かしたりしない。捨て札で覆われる場合と、山札で覆われる・シャッフルされる場合を区別する。
- **書庫の脇のカードは手札とは別。** 複数の進路のリアクションは個別に扱い、途中のシャッフルによる移動失敗を反映する。
- **移動の失敗と効果全体の失敗は別。** 玉座の間で実験を再使用する場合、実験が山に戻った後でも2回目のドロー等は解決される。
- **持続の種類だけで場に残さない。** 女魔術師・追いはぎ等による置換、不発、再使用、場から離れたカード、未解決の将来効果を区別する。
- **老魔女で廃棄する呪いは手札から。** 直前に獲得して捨て札に置かれた呪いを代わりに廃棄しない。
- **神風の旧山は終局JSONにも残る。** 発動の記録と公共サプライの表示フラグを使って旧山・新山を区別する。手札や場に残る旧カードは消さない。基本山の減少済み枚数を維持し、新山の初期枚数に終局の残数を使わない。

ルールが曖昧な場合は、[日本語Wiki](https://wikiwiki.jp/dominiondeck/)と公式ルール・エラッタを確認してください。UIの見せ方はDominion Onlineを参考にします。構造化された明示の記録を優先し、印刷効果から補う場合は二重加算を防いでください。

### ビルドと検証

編集用ソース一式を展開したルートで実行します。ビルドにはPython 3、JavaScriptのテストにはNode.jsを使います。

```sh
python3 work/build-v6.py
node work/verify-v66-transfers.js
node work/verify-v67-effects.js
node work/verify-v68-landscape.js
node work/verify-v69-movement.js
node work/verify-v691-wind.js
python3 work/verify-v6-structure.py
```

ビルドされた `dominion-replay.html` を、公開用の `index.html` として配置します。変更箇所に関連する `work/verify-*.js` も実行してください。一部のテストは別途棋譜ファイルを必要とします。ファイルがない場合の未実施とテスト失敗を混同しないでください。

不具合修正では、対象のログ行・処理の文脈・移動元と移動先を確認してから修正し、該当ケースをテストへ追加してください。各時点で所有枚数と山札・手札・捨て札・場・マットの合計が一致すること、順方向と巻き戻しの両方を確認してください。公開前には完成した `index.html` をChromeでも操作し、ソースのテスト結果と実画面の確認結果を区別して報告してください。

すべてのカード・全組み合わせを完全に再現できる保証はありません。個体IDや処理順が記録されていない場合の限界を明示してください。実際の棋譜・アカウント情報を配布HTMLや公開テストへ無断で埋め込まないでください。

## 不具合を報告するとき

使用したバージョン、ブラウザ、該当ターン／ログ行、期待する動作、実際の表示を知らせてください。共有してよい記録があると再現しやすくなります。
